The instruments

The audit is a product, so it has tools rather than a folder of half-named documents. These three run in the browser, keep their state on the device, and hand work to each other as plain JSON files. Nothing is uploaded anywhere.

Step 02

Audit worksheet

Twenty-one questions across six areas of the practice, asked in the order that keeps software out of the conversation until the week has been described. Exports the bottlenecks.

 Step 03

Prescription builder

Takes the worksheet, puts a named tool against each bottleneck, and computes the arithmetic. Prints the five-page report. Warns when the total falls under the five-hour guarantee.

 Reference

Vendor register

Every tool we would consider recommending, and the honest state of what we have checked — above all whether the vendor will sign a BAA.

Why these are plain files

A practice's week, written down, is sensitive even when it carries no patient names. Keeping every tool client-side means there is no database to breach, no account to manage and no vendor to add to anybody's risk assessment — including ours. The cost is that clearing your browser clears your work, so both tools export a file and say so.
